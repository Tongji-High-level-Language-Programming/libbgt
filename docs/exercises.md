# libbgt 作业题库

本文档面向教师，是 libbgt 的作业题库：每道题一个完整小游戏，配分步引导、
验收点与参考实现。题库与 `demo/` 目录一一对应——demo 就是参考答案，学生
先做后看。编号顺序即课程线：v0.1 递归与状态机 → v0.2 碰撞 → v0.2 随机 +
v0.3 存档 → v0.3 全家桶综合。

## 总览

| # | 题目 | 训练焦点 | 难度 | 参考实现 |
|---|------|----------|------|----------|
| 1 | 汉诺塔（递归 + 状态机） | 状态机思维 + 递归接入 | ★★ | `demo/02_hanoi.cpp` |
| 2 | 打砖块（碰撞 + 音效） | 实时循环 + 碰撞反弹 + 音效 | ★★ | `demo/03_breakout.cpp` |
| 3 | 扫雷（随机 + 存档） | 鼠标交互 + 随机 + 递归展开 + 存档 | ★★★ | `demo/04_minesweeper.cpp` |
| 4 | 太空射击（全家桶综合） | 图片 RST + 碰撞 + 存档 + 声音 + 错误面板 | ★★★★ | `demo/05_shooter.cpp` |

## 设计原则

- 一个作业只引入一个新概念，作业描述中明确写出"本作业要学的是 X"。
- 结果可观察：每个作业的验收标准都是窗口里能一眼看出的行为。
- 支架式：前几个作业给出骨架代码与关键片段，随进度逐步撤除。
- 先状态图，后代码：涉及状态切换的作业，先画状态图再写程序。
- 前置知识明确标注，避免作业卡在库之外的概念上。

## 1. 汉诺塔（递归 + 状态机）

**目标**：800×600 窗口里实现完整汉诺塔演示：开始/游戏中/完成三态流程，
游戏中支持手动游玩与递归自动求解。汉诺塔是课程反复使用的教学载体，
课堂终端版递归在这里原样接入图形界面——同一个递归函数，输出从终端文字
变成图形动画。

**训练焦点**："程序 = 循环中持续更新的状态"心智模型（状态机思维）；
跨帧状态变量 → 隐式状态（bool）→ 显式状态机的渐进；课堂递归"改输出
不改算法"接入。

**前置**：变量、条件、循环、数组、递归（课堂终端版 hanoi）。

**分步引导**（作业 0 → 5，每步可运行）：

### 作业总览

### 作业 0：画出初始局面（无状态）

**新概念**：无。本作业只接触坐标、颜色、形状与文本——一切后续作业的地基。

**题目**：800×600 窗口，底部画三根柱子（窄矩形）；左柱上叠 3 个圆盘（宽度递减
的填充矩形，颜色不同）；窗口顶部用中文绘制标题"汉诺塔"。

**骨架**：

```cpp
#include "bgt.h"

int main()
{
    bgt_open_window(800, 600, "汉诺塔");
    bgt_set_background(BGT_WHITE);

    while (bgt_window_is_open()) {
        // TODO: 画三根柱子
        // TODO: 在左柱上叠 3 个圆盘（宽度递减）
        // TODO: 画标题
        bgt_update_window();
    }

    bgt_close_window();
    return 0;
}
```

**要点**：盘子宽度、位置等几何量用常量或变量表达，先算坐标再写数字；圆盘 x 坐标
从柱子中心向两侧展开。

**验收**：窗口显示三柱三盘；把窗口尺寸改成 640×480 后程序依然正确（只用改窗口
参数和常量）。

**教师评分要点**：是否用常量表达几何尺寸；是否理解左上角坐标系。

**变体**：盘数改为常量 `kDisks = 4`；用 `bgt_rgb()` 让盘色按盘号渐变。

### 作业 1：键盘选择柱子（第一个跨帧状态）

**新概念**：跨帧状态变量——变量声明在循环外，在帧与帧之间存活。

**题目**：左右方向键让一个高亮标记（柱子顶部的"▼"文本）在 0/1/2 号柱之间移动；
窗口显示当前选中柱号。

**关键片段**：

```cpp
int selected = 0;   // 跨帧状态：当前选中的柱子
while (bgt_window_is_open()) {
    if (bgt_key_is_down(BGT_KEY_LEFT))  selected = selected - 1;
    if (bgt_key_is_down(BGT_KEY_RIGHT)) selected = selected + 1;
    if (selected < 0) selected = 0;   // 不越界
    if (selected > 2) selected = 2;
    // ... 绘制：高亮画在 selected 号柱子上
    bgt_update_window();
}
```

**要点**：每帧"读输入 → 改状态 → 画状态"；`bgt_key_is_down` 是"按住就持续生效"。

**验收**：按住方向键高亮连续移动；到边缘不再越界；松开后保持不动。

**教师评分要点**：变量是否声明在循环外；边界处理是否正确。

**变体**：把 `is_down` 换成 `just_pressed`，观察行为差异并写一段解释——为作业 2
的事件语义做铺垫。

### 作业 2：拿起与放下盘子（事件语义 + 隐式状态）

**新概念**：事件 vs 状态——`bgt_key_just_pressed` 回答"这一帧刚按下吗"，是瞬时
事件；`is_down` 回答"现在按住吗"，是持续状态。另外引入第一个隐式状态：`bool`
变量 holding。

**题目**：在作业 1 基础上：

- 按空格"拿起/放下"：若未拿起，把选中柱顶部的盘子取出，绘制时它悬在被取出的
  柱子上方（水平位置不变）；若已拿起，放到当前高亮柱上（作业 3 再给放下动作
  加上动画）。
- 放下时检查汉诺塔规则：目标柱为空，或目标柱顶盘大于手中的盘；不合法则拒绝，
  保持拿起状态并给出可见反馈（如红色文字提示）。
- 放下成功时移动次数 +1，窗口显示移动次数。

**数据表示建议**（前置：数组）：

```cpp
const int kMaxDisks = 3;
int towers[3][kMaxDisks] = {{3, 2, 1}, {}, {}};  // 每柱从下往上存盘号
int heights[3] = {3, 0, 0};
int moves = 0;              // 跨帧状态
bool holding = false;       // 隐式状态：是否拿着盘子
int held_disk = 0;
```

**要点**：`holding` 是一个不叫"状态机"的状态机——只有两个状态，按空格切换；
作业 4 会把这类状态正式命名为状态机。注意数组边界：取顶盘是 `heights[i] - 1`。

**验收**：拿起后盘子跟随高亮柱移动；非法放置被拒绝且画面有反馈；合法放置计数 +1；
任何操作不越界、不崩溃。

**教师评分要点**：事件与状态的区分是否体现在代码里；合法性判断是否完整。

**变体**：拿起时显示"当前拿着 3 号盘"的文本；按 ESC 把盘子放回原柱。

### 作业 3：平滑移动动画（时间驱动状态）

**新概念**：动画进度也是跨帧状态；`bgt_delta_time()` 让动画速度与帧率无关。

**题目**：放下盘子时不再瞬移：记录起点柱、终点柱和进度 `t`（0→1），每帧
`t += bgt_delta_time() * 速度`，盘子位置 = 起点 +（终点 − 起点）× t；动画期间
按空格无效。

**关键片段**：

```cpp
int anim_from = 0, anim_to = 0;   // 起点柱、终点柱
double anim_t = 1.0;              // 1.0 = 当前没有动画
const double kSpeed = 2.0;        // 每秒完成的移动次数

// 放下成功时：anim_from = 原柱; anim_to = 目标柱; anim_t = 0.0;

if (anim_t < 1.0) {
    anim_t = anim_t + bgt_delta_time() * kSpeed;
    if (anim_t >= 1.0) {
        // 落盘：更新 towers / heights，动画结束
    }
}
// 动画中盘子的 x = 柱x(anim_from) + (柱x(anim_to) - 柱x(anim_from)) * anim_t
```

**验收**：把帧率上限分别设为 30、60、不限制，动画速度肉眼一致；动画中按空格无效；
动画结束后盘子确实落位。

**教师评分要点**：动画是否用 `delta_time` 而非固定步长；"动画中"是否真的挡住了
输入。

**变体**：用 `bgt_total_time()` 让完成后的文字闪烁。

### 作业 4：三态流程（显式状态机）

**新概念**：显式状态机——状态变量 + 转移条件 + 各状态各自的行为。

**题目**：程序有三个状态：开始画面（标题 + "按空格开始"）→ 游戏中（作业 3 的
全部玩法）→ 完成画面（所有盘都在右柱："按 R 重开"）。用 `int` 常量表示状态。

**先画状态图，再写代码**：

```text
[开始] --按空格--> [游戏中] --全部盘到右柱--> [完成]
   ^                                            |
   |----------------按 R 重开--------------------|
```

**关键片段**：

```cpp
const int kStateStart = 0;
const int kStatePlaying = 1;
const int kStateDone = 2;
int state = kStateStart;

while (bgt_window_is_open()) {
    if (state == kStateStart) {
        // 画标题；按空格 -> state = kStatePlaying
    } else if (state == kStatePlaying) {
        // 作业 3 的全部逻辑；全部盘到右柱 -> state = kStateDone
    } else if (state == kStateDone) {
        // 画完成画面；按 R -> 重置塔与计数, state = kStateStart
    }
    bgt_update_window();
}
```

**要点（状态机三问）**：现在是什么状态？什么条件离开？离开后做什么？每个状态只
关心自己的事，其他状态的输入一律忽略。

**验收**：三态完整流转；非法按键在任何状态都不造成崩溃或错误行为；完成判定只在
"游戏中"生效；重开后塔与计数都复位。

**教师评分要点**：先收状态图再收代码；检查各状态的输入隔离。

**变体**：增加"暂停"状态（P 键切换，画面冻结）——练习"状态内的状态"。

### 作业 5：递归求解接入（递归 → 图形）

**新概念**：无（递归已学）。本作业是把课堂上的递归汉诺塔"换个输出"：同一个函数，
从打印终端文字变成驱动图形动画。

**题目**：课堂终端版 `hanoi(n, from, to, via)` 每步 `printf`——现在改为把每步
写进移动序列数组 `moves[kMaxSteps][2]`（每行是 from→to）。在"游戏中"状态增加
演示模式：按 S 生成序列，之后按空格逐步执行一步（可扩展为按住自动播放）。3 盘
应得到 7 步，4 盘 15 步。序列播放完毕后进入完成状态（复用作业 4）。

**教学要点**：递归函数本身一行不改，只改"记录方式"——这正是可视化的意义；建议
课堂并排运行终端版与图形版，学生直观看到"改输出不改算法"。序列写入位置用
全局变量或引用参数实现。参考实现见 `demo/02_hanoi.cpp`。

**验收**：逐步播放的序列与手算结果、终端版输出完全一致；步数 = 2ⁿ − 1；播放完
进入完成状态。

**教师评分要点**：检查学生是否真的复用了课堂递归（而非重写循环解法）；对照两版
代码差异应只有几行。

**变体**：按住空格连续执行；加入"演示速度"调节（`bgt_mouse_wheel()`）。

**验收点**：

- [ ] 窗口显示三柱三盘，改窗口尺寸后程序依然正确（作业 0）
- [ ] 按住方向键高亮连续移动，边缘不越界（作业 1）
- [ ] 拿起/放下遵守汉诺塔规则，非法放置有可见反馈，合法放置计数 +1（作业 2）
- [ ] 帧率上限 30/60/不限时动画速度肉眼一致；动画中输入被挡住（作业 3）
- [ ] 三态完整流转，各状态输入隔离，重开复位（作业 4）
- [ ] 演示序列 = 2ⁿ − 1 步，与终端版输出一致（作业 5）

**参考实现**：`demo/02_hanoi.cpp`（先做后看）。

### 状态机教学要点

- 三问：现在是什么状态？什么条件离开？离开后做什么？
- 状态图先于代码（纸面练习，可单独计分）。
- 用 `int` 常量 + `if/else` 即可，不引入类、结构体、指针——与库本身的教学约束一致。
- 状态与数据分离：状态回答"程序处于哪个阶段"，数据回答"局面长什么样"。
- 叙事线：作业 1–3 是隐式状态（变量即状态），作业 4 正式命名状态机，作业 5
  把课堂递归算法接入既有状态机——算法与状态各司其职。

### 与课程的衔接

- 递归：课堂先讲终端版 `hanoi`，作业 5 原样接入图形库。
- 终端可视化：作业 0–3 提供图形基础，作业 5 完成"同一函数、两种输出"的对照演示。
- 建议课堂上并排运行终端版与图形版汉诺塔（参考 `demo/02_hanoi.cpp`），让
  学生亲眼看到"改输出不改算法"。

### 教师说明（汉诺塔）

- 课时：约 5–7 课时（作业 0–3 各 1 课时，作业 4–5 各 1–2 课时）。
- 支架撤除：作业 0–1 给完整骨架，作业 2–3 给关键片段，作业 4–5 只给结构提示。

## 2. 打砖块（碰撞 + 音效）

**目标**：800×600 窗口，挡板接球清空砖阵；3 命 3 关，每关砖阵为字符画
预设并随机抽 3 块缺席——每局微不同。球只用速度分量运动，反弹零三角函数。

**训练焦点**：`bgt_delta_time()` 驱动的实时循环；`bgt_hit_circle_rect`
（球-挡板）与 `bgt_hit_rect_rect`（球-砖）连续坐标碰撞；按命中位置定
反弹角的速度分量公式；`bgt_load_sound`/`bgt_play_sound` 音效反馈。

**前置**：跨帧状态变量与显式状态机（题 1）；数组。

**分步引导**（每步可运行）：

- **Step 1 画出战场**：砖阵（字符画 + 行配色）、挡板、静止的球——运行
  即见完整局面。
- **Step 2 挡板移动**：←/→ 用 `bgt_key_is_down` + `delta_time` 平滑移动，
  球贴在挡板上跟随。
- **Step 3 发球与撞墙**：空格发球，球撞左右上三面墙时翻转对应速度分量
  ——球在场地内永不停止。
- **Step 4 挡板反弹**：命中位置定 vx 比例，
  `vy = -sqrt(v² − vx²)`——打左飞左、打右飞右、正中直上。
- **Step 5 砖块碰撞**：`bgt_hit_rect_rect` 命中即消砖、翻转分量、+10 分。
- **Step 6 生命与关卡**：球落底扣命回挡板；清空砖阵过关（奖励
  = 关卡号 × 50），3 关通关或命尽进入结束画面。
- **Step 7 音效**：反弹/消砖/失球/过关四音（加载失败不致命，判编号
  再播）。

**验收点**：

- [ ] 反弹只用速度分量翻转，无三角函数
- [ ] 发球前球贴挡板移动；挡板反弹角随命中位置变化
- [ ] 每关砖阵随机缺 3 块，每局不同
- [ ] 3 命耗尽进结束画面；过关计奖励分；三关后进通关画面
- [ ] 四种音效触发正确；删掉 wav 文件运行不崩溃（静默降级）

**参考实现**：`demo/03_breakout.cpp`（先做后看）。

## 3. 扫雷（随机 + 存档）

**目标**：9×9 棋盘 10 雷经典扫雷：左键翻格、右键插旗、首踩不炸、翻到
0 递归连锁展开；程序退出自动存档，下次启动可续玩上局。

**训练焦点**：`bgt_random` 不放回采样（洗牌候选数组取前 N）；鼠标左/
右键事件；递归展开（题 1 递归的下一站——这次递归驱动的是"翻格子"）；
`bgt_load`/`bgt_save` 双场景存档：[战绩]（胜场、最快纪录）与 [局面]
（盘面 81 字符串、雷位 81 字符串、已用秒数）。

**前置**：二维数组；递归（题 1）；字符串基础。

**分步引导**（每步可运行）：

- **Step 1 画棋盘**：9×9 未翻格子，鼠标悬停/点选能定位到格子。
- **Step 2 翻格与数字**：左键翻开的格子显示邻域雷数。
- **Step 3 首踩不炸**：第一次点击后才布雷（排除首格 3×3 邻域），洗牌
  候选格数组取前 10——首格必是 0。
- **Step 4 连锁展开**：翻到 0 递归翻邻居——开局一次大面积展开。
- **Step 5 插旗**：右键在未翻格上插旗/拔旗，剩余雷数 = 10 − 旗数。
- **Step 6 胜负与计时**：安全格翻遍胜利（记最快用时）；踩雷失败并展示
  所有雷。
- **Step 7 [战绩] 存档**：胜场与最快纪录落盘——关掉重开还在。
- **Step 8 [局面] 续玩**：退出自动存盘面/雷位/秒数；启动检测到未完成
  局面提示按【L】续玩，计时衔接正确。

**验收点**：

- [ ] 首踩必不炸且必展开一片
- [ ] 已翻格左键无副作用；旗只出现在未翻格
- [ ] 连锁展开无死循环、无漏翻
- [ ] 胜场/最快纪录跨次运行持久
- [ ] 续玩后局面与计时与退出前一致；胜利后的局不再被续玩

**参考实现**：`demo/04_minesweeper.cpp`（先做后看）。

## 4. 太空射击（全家桶综合）

**目标**：800×700 太空射击：飞船左右移动、空格射击；敌人两型——普通
直落、快速敌同图缩小 + 自旋翻滚（RST 展示）；波次生成、波间加速；连击
倍数、星空视差、爆炸圆环；最高分/最高波次落盘，BGM 循环。资产缺失时用
`bgt_draw_error` 画错误面板——错误 API 的收官展示。

**训练焦点**：`bgt_load_image`/`bgt_draw_image` 与
`bgt_scale_image`/`bgt_rotate_image`（同一文件两个编号独立变换）；
`bgt_hit_circle_rect`（子弹-敌）+ `bgt_hit_rect_rect`（敌-船）；
`bgt_play_music`/`bgt_play_sound`；[纪录] 存档；`bgt_error_count`/
`bgt_draw_error` 面板。

**前置**：题 1–3 全部（状态机、数组管理、碰撞、存档思路）。

**分步引导**（每步可运行）：

- **Step 1 星空视差**：60 颗星两层速度下滚——开窗即有生命感。
- **Step 2 飞船与射击**：←/→ 移动；空格发射（帧计数冷却），子弹数组
  出屏回收。
- **Step 3 敌人生成**：波次数量 = 4 + 波号、随机横坐标、直落下落。
- **Step 4 击落敌机**：子弹-敌碰撞双双消亡，爆炸圆环 12 帧，计分。
- **Step 5 快速敌**：同图 `bgt_scale_image(0.7)` + `bgt_rotate_image`
  自旋——同一张图的两个编号、两种姿态。
- **Step 6 被撞与无敌**：敌-船碰撞扣命 + 1.5 秒无敌闪烁；3 命结束；
  敌漏过底部不扣命。
- **Step 7 连击倍数**：2 秒内连续命中递增，≥5 分数 ×2、≥10 ×3。
- **Step 8 BGM 与音效**：`05_bgm.wav` 循环 + 射击/爆炸/被击三音。
- **Step 9 [纪录]**：最高分/最高波次落盘；结束画面破纪录提示"新纪录！"。

**验收点**：

- [ ] 快速敌明显更小且持续旋转，与普通敌姿态可区分
- [ ] 连击 2 秒断档后倍数清零；倍数只取 ×1/×2/×3 整数
- [ ] 被撞后 1.5 秒无敌闪烁；漏过底部的敌不扣命
- [ ] 波次推进时敌人变多且变快
- [ ] 最高分/最高波次跨次运行持久
- [ ] 删掉 05_*.png 运行：显示错误面板而非崩溃
